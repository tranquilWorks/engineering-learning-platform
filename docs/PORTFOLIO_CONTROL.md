# Portfolio Control Integration

The repository intentionally contains product-specific `AGENTS.md`, engineering requirements, a bounded local foundation batch, deterministic verification, and a Portfolio Control intake message. Managed harness files such as `.portfolio-harness.json` must be generated by `kpbianco/portfolio-control`; they are not fabricated in this scaffold.

## Onboard after pushing the remote repository

```bash
cd ../portfolio-control
portfolio add-repo kpbianco/engineering-learning-platform \
  --profile product-data \
  --file ../engineering-learning-platform/docs/PORTFOLIO_ONBOARDING_REQUEST.md \
  --plan-policy auto \
  --target-policy pr-only
```

Expected governed sequence:

1. review/merge the planning PR in Portfolio Control;
2. review/merge the target harness PR in this repository;
3. review/merge the separate Portfolio Control pointer PR;
4. run `portfolio go engineering-learning-platform --max-batches 1`;
5. retain exact validation and residual-risk evidence for each batch.

The sibling folder `engineering-learning-platform-portfolio-control/` is a proposed product-pack seed for review. The operator-generated plan remains authoritative.
