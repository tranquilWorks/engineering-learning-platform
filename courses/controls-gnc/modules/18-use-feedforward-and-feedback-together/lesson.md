# Use Feedforward and Feedback Together

**Guiding question:** What inputs, observable effects, and failure modes matter when you use Feedforward and Feedback Together?

Separate planned acceleration from feedback correction during trajectory tracking. This native lab preserves the source experiment while making the levers, diagnostics, and recovery available directly in the learning platform.

## Predict before running

Feedforward should reduce nominal lag while feedback remains necessary for disturbance rejection. Write down the mechanism you expect—not only the trace direction—before moving a control.

## Model and equations

- $$u=u_{ff}+K_pe+K_d\dot e$$ — Feedforward supplies known demand; feedback corrects mismatch.
- $$u_{ff}=\ddot x_d$$ — For a unit-mass model, desired acceleration is the nominal inverse input.

The GUI evaluates these equations deterministically. Read the metric cards and both plots together: a pleasing response can still conceal poor authority, weak conditioning, stale data, or invalid assumptions.

## Two one-variable sweeps

1. Sweep `feedforward_scale` through [0.0, 1.0, 1.5]. Hold every other control fixed and explain the causal chain from equation to trace to metric.
2. Sweep `feedback_scale` through [0.0, 1.0, 2.0]. Compare the changed mechanism plot with your first prediction.

Do not tune both levers at once until you can identify which term each lever changes.

## Intentionally broken case

The broken case reverses feedforward sign, commanding acceleration away from the plan. Predict the signature before enabling **broken mode**.

## Recovery

Disable the broken case and verify inverse-model sign conventions. A recovery is complete only when you can name the failed assumption and point to the metric or trace that confirms it.

## Common mistakes

- Treating a simulation trace as proof about hardware or production behavior.
- Changing multiple controls at once and losing causal attribution.
- Reading only the final value while ignoring transient effort, conditioning, delay, or saturation.
- Hiding a failed assumption by retuning instead of reproducing and explaining it.

## Teach-back

In two minutes: state the governing equation, explain what each live lever changes, identify the broken assumption, and justify the recovery with one visible metric and one plot feature.

# P18 lesson: Use Feedforward and Feedback Together

## Guiding question

What inputs, observable effects, and failure modes matter when you use Feedforward and Feedback Together?

## Compounds on

P17 — Balance State Error and Control Effort with LQR. P17 used the damped cart and chose a gain from
state-error and effort prices. P18 retains its exact baseline gain and asks a different question:
how should that feedback correction be combined with an input already known from a feasible plan?
In practice the error uses P16's state estimate; the deterministic lesson uses exact state to isolate
the command mixer.

## Mental model

Think of moving a tray along a route. Feedforward is the route card: it says when the nominal cart
must accelerate before the position error grows. Feedback is the observer watching the tray: it adds
a correction when an unplanned shove makes actual motion differ from the route. One anticipates a
known cause; the other reacts to an observed effect.

The reference is generated by the same held-input damped-cart model as the plant:

```text
x_ref[k+1] = A*x_ref[k] + B*u_plan[k]
u_cmd[k]   = s_ff*alpha*u_plan[k] + beta*K*(x_ref[k]-x[k])
x[k+1]     = A*x[k] + B*(u_cmd[k]+d[k])
```

The planned value is a plant-input acceleration command in `m/s^2`; it is not the kinematic second
derivative of an asserted sinusoidal position. The external disturbance enters separately so it is
never mislabeled as actuator command.

## What the two levers reveal

- **Feedforward scale `alpha`:** with the disturbance removed, `alpha=1` reproduces the feasible plan
  exactly. Tracking error and feedback correction are zero. At `alpha=0`, stable feedback eventually
  follows but must create the entire planned input from error. Equal under- and over-scaling produce
  opposite error signs and equal quadratic error/correction metrics.
- **Feedback scale `beta`:** with matched feedforward and the load pulse restored, `beta=0` tracks
  perfectly until the load but cannot erase its lasting position offset. Positive values move the
  error poles inside the unit circle. More authority reduces error and recovery time while increasing
  the squared feedback-correction integral over the fixed experiment.

Squared feedforward and feedback integrals do not add to total-command effort: squaring their sum
also creates a cross term. These integrals have `m^2/s^3`; they are not mechanical or electrical
energy.

## Deliberately broken assumption

The reference generator and command mixer must share the same actuator sign convention. The broken
case sends `-u_plan` while generating the reference with `+u_plan`. Feedback stays stable, but it now
opposes a persistent deterministic wiring error. Large opposing feedforward and feedback components,
larger tracking error, and much larger correction effort identify the fault. A fresh correct-sign
call exactly recovers the baseline because the model has no hidden or persisted state.

## Misconceptions to correct directly

- Feedforward is not open-loop guesswork here; its source is the declared feasible reference input.
- Feedforward does not observe disturbance error, even when its nominal tracking is exact.
- Feedback does not know what motion is planned; it reacts only after reference and actual state differ.
- Adding feedforward does not make feedback unnecessary, and adding feedback does not repair bad units
  or polarity without spending correction authority.
- The feedback scale changes a declared fixed gain; it does not recompute P17's LQR optimum.
- The P17 gain is retained at its `0.02 s` design interval and held fixed for display-grid variations.
- Independent reference simulation is not MATLAB-runtime, UI, hardware, HIL, or field evidence.

Ask one observation question at a time. Request the teach-back only after executable checks pass.

## Learner sequence

1. Read the guiding question and the command mixer before running code.
2. Predict only which component reacts when the fixed load begins at `4 s`.
3. Visualize the baseline reference and actual position. They coincide before the load; feedback then
   corrects the tracking error and returns it to the labeled tolerance.

5. Remove the disturbance and sweep only feedforward scale `alpha`. Observe that the changed view has

8. Explain the change from the poles of `A-beta*B*K` and the error signal that drives feedback.
